# R2 storage boundary (#17)

Implemented and verified against **explicit local HTTP S3 fixtures**, not an actual Cloudflare account. R2 buckets/credentials are not configured; no cloud upload, provisioning, billing action or hosted claim occurred. The source/model/partition and static evaluation are unchanged.

`service.asset_storage.TrustedAssets(manifest_path, expected_sha256)` is the source boundary for #18. The expected digest and manifest are trusted deployment configuration, never request fields. It checks schema, committed frozen model and partition checksums, exact held-out count, valid unique membership, static completeness, safe paths and per-file size/SHA256. Only manifest keys are accessible: `assets/{manifest_sha256}/{relative_path}`. It never uses bucket listing as membership authority.

Use `with assets.selected(client_from_env('assets'), bucket, selected_patient_ids, parent=private_scratch) as root:`. This downloads only selected patients' raw objects plus the five required small static/model/outcome files. Configure engine `raw_dir=root/'raw'`, model `root/'model.json'`, outcomes `root/'outcomes.csv'`. For scoring/approval continuations pass `scans=False`: selection/model/manifest binding is still checked, but only verified static files are downloaded; scan bytes are never fetched again for scoring persisted features. The yielded root is private (0700). Every download is streamed in 1 MiB chunks through size/SHA256 validation before the context yields. Invalid/duplicate/non-held-out selections, path traversal, missing/corrupt/truncated transfers fail before imaging; all scratch, including partial bytes, is removed on success or exception. Cleanup cannot run after container SIGKILL; use ephemeral Modal scratch, not persistent shared source mounts. Source credentials stay on the worker; ordinary Render browsing must never initialize this source downloader or materialize the scans.

`service.object_storage.ArtifactStore(client,bucket,prefix='runs',max_bytes=4_000_000)` is the generated-byte boundary for #16/#18:

- `publish(run_id, artifact_id, data:bytes, media_type)` returns `{storage:'s3',run_id,artifact_id,key,sha256,size_bytes,media_type}` only after an immutable conditional upload and independent GET verification. Key is `{prefix}/{run_id}/{artifact_id}`. Server-derived IDs accept only ASCII alphanumeric, dash, underscore (1–160 characters). Repeating identical publication is idempotent; different bytes or type for the same logical ID fail without replacing it. Use stable event/phase/attempt identifiers with the durable operation fence. Upload first, then conditionally commit reference metadata under that fence; rejected late writes leave an unreferenced object rather than reviving a canceled run.
- `read(run_id, persisted_reference)` checks run ownership and derives the key again, bounds size and validates actual SHA256, returning bytes. **The caller must authorize the per-run capability first**; a run ID alone is not authorization. Browser-provided keys/references are never accepted. Return only the existing artifact route after authorization, not the raw reference/key in public event serialization. Supported outputs are PNG, SVG, JSON, CSV and generic octet-stream, each bounded to 4 MB by default; mask NumPy volumes remain worker-local as before.
- `ArtifactStore.from_env(role='results')` creates the real boto3 adapter. `presign(run_id,reference,expires=60)` optionally creates a fresh 1–300-second GET after verification. Current integration can keep bounded authenticated byte proxying; it avoids bucket browser CORS and fits existing Blob retention. A URL is not durable History: preserve `captureEvent` fetching bytes and storing Blobs in IndexedDB. Do not persist credentials or depend on old signed URLs. Per-run capability authorization remains in #16's application route/repository.

No scan bytes belong in PostgreSQL or a Modal call argument/return. Neon stores trusted structured metadata and artifact references; Modal uploads generated bytes directly to R2. Ordinary browsing uses existing saved structured results/static examples; this adapter does not substitute prepared features for live extraction.

## Bootstrap and real-data dry run

The existing `scripts.release_assets create` prepares the held-out-only manifest anchored to committed `docs/model-v1-manifest.json`, without changing source bytes. Do not regenerate the partition, model or features. The verified existing manifest is outside Git at `/private/tmp/mini-nota-implementation/release-assets-v1.json`, SHA256 `afb52b9c96b756890f4050f0f3b02157bc2618fa4892dfd68cbd0f6f4b637217`.

From the repository with the source data available:

```bash
python -m scripts.r2_assets \
  --manifest /path/release-assets-v1.json \
  --expected-sha256 afb52b9c96b756890f4050f0f3b02157bc2618fa4892dfd68cbd0f6f4b637217 \
  --prepared /path/library-v1 --bundle /path/cox-v1/model.json \
  --plan-output /private/path/r2-plan.json
```

Default is a credential-free dry run: validates **every local file** before reporting anything uploadable. A prepackaged tree may use `--root /path/assets` instead. The optional plan lists every exact key/size/checksum for review. Add `--upload` only with the bootstrap credentials configured. Upload always validates all sources before the first remote mutation, writes only the manifest entries, uses conditional immutable PUT, verifies each actual remote object's complete bytes, and on rerun verifies/skips existing complete objects. It does not trust multipart ETags or uploader-supplied metadata. A corrupt existing key fails closed rather than silently replacing a version; repair/rebootstrap is an operator task. Retry the same command after network failure. This is object-level resume, not partial-byte/multipart resume.

Actual dry run in this checkout verified **82 held-out patients, 10,251 files, 5,459,433,502 total bytes** (raw scans: 10,246 files / 5,459,320,394 bytes). Zero objects uploaded; source files unchanged. The detailed reviewable plan is external at `/private/tmp/mini-nota-implementation/r2-assets-v1-plan.json` and contains no credentials. The manifest must ship as immutable worker configuration (or a separately pinned config artifact); bucket membership alone is never trusted.

## Credentials, permissions and CORS

`deploy/r2.env.example` documents role-specific configuration. Each role uses `R2_{ASSETS,UPLOAD,RESULTS}_{ENDPOINT_URL,BUCKET,ACCESS_KEY_ID,SECRET_ACCESS_KEY}`; results may set `R2_RESULTS_PREFIX` (one safe token). R2 region is `auto`, S3 signing is v4. Keep **two private buckets**, public access disabled. Scope source-read credentials to the source bucket; keep source-write/bootstrap credentials operator-only. Give Modal results read/write for conditional publication and verification; Render needs results-read only under the same env names in its own environment. Never inject the upload/source credentials into Vercel or browser code. Tokens must be configured and permissions checked against actual Cloudflare buckets before claiming cloud verification. The adapter does not provision tokens or enforce provider-side bucket policies.

Existing same-origin authorized artifact proxying needs no R2 browser CORS. If using the optional signed GET path, configure the exact frontend origin(s), GET/HEAD only, and required response headers (`Content-Type`, `Content-Length`, optional checksum metadata); do not enable public bucket listing or wildcard write access. Verify real browser fetch/CORS against the actual account. Signed URLs remain temporary access grants; avoid logging them.

## Verification and limits

The approved storage seam is exercised over actual loopback HTTP with Moto as an explicitly labeled S3 fixture, plus a deliberately truncated HTTP fixture. Tests cover run ownership, restart byte durability, identical/different duplicate publication, size/checksum corruption, manifest pin/model mismatch, traversal/non-held-out/missing/duplicate entries, source corruption before mutation, resumable object verification, selected-only private download and cleanup after missing/corrupt/incomplete transport. These are software-contract checks, not real R2 validation or imaging-performance measurements.

Run in a dedicated environment to keep Moto's server dependency constraints out of the app runtime:

```bash
python -m venv --system-site-packages /tmp/mini-nota-storage-fixture
/tmp/mini-nota-storage-fixture/bin/python -m pip install -r deploy/requirements-storage-fixture.txt
REQUIRE_STORAGE_FIXTURE=1 /tmp/mini-nota-storage-fixture/bin/python -m pytest tests/test_object_storage.py -q
```

The explicit flag makes missing fixture dependencies fail collection. The ordinary app suite may skip this named module when Moto is absent; CI has a separate mandatory fixture step. Boto3 and its resolved transport dependencies are production-pinned separately. Do not install Moto into the production runtime. App/browser authorization and byte-saving integration must be verified alongside #16/#18; this module intentionally does not modify `service.app` or browser `captureEvent`.

Cloudflare documents atomic conditional PUT in its [conditional operations guide](https://developers.cloudflare.com/r2/api/s3/conditional-operations/) and [consistency model](https://developers.cloudflare.com/r2/reference/consistency/). The adapter uses `If-None-Match: *` and its own streamed SHA256 verification; the SDK is configured to send automatic transport checksums only when required. This documented support is separate from the still-pending real account canary.
