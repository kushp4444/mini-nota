# Verified tumor masks (#4)

The application now runs real QC then a discrete `/masks` engine tool for each passing patient. `run.patients` retains the existing QC contract. `run.stage_results` adds `qc` and `masks` arrays; every result event is `{stage, patient}`. QC failures never enter mask construction. A mask failure emits its patient, safe code/reason and exclusion in both patient results and the agent timeline; later patients continue. This slice ends after masks and explicitly says that feature/scoring orchestration is not yet connected.

## Physical geometry

`load_series` verifies one regular single-frame CT grid: shared study/series/frame, orthonormal orientation, finite positive per-slice PixelSpacing, consistent dimensions, unique SOP instances, projected slice order and regular spacing. Slice gaps and in-plane displacement must agree within 0.01 mm. Unsupported sheared/nonuniform grids fail explicitly; no unit-spacing substitution remains. Array axes are `(slice,row,column)` (`zyx`), with spacing `(slice,row,column)` in mm. DICOM's first orientation vector advances columns, and its PixelSpacing order is `(row,column)`. SliceThickness is metadata only, never the source of volume spacing. Every slice applies its own HU rescale.

The existing `rtstruct_to_mask` interface still uses rt-utils for RTSTRUCT validation and ROI contour selection. Its corrected rasterization adapter fixes rt-utils 1.2.x's swapped unequal pixel spacing and rectangular image allocation. It checks the ROI/frame/series and each contour's referenced SOP, physical slice plane, coordinates and image bounds. Only `CLOSED_PLANAR` contours are supported; nested polygons use parity to preserve holes. Return axes remain `(row,column,slice)`, and engine/CLI feature paths transpose explicitly to match CT. Features receive the same verified spacing, LPS origin and direction; `extract_one`/`extract_all` no longer invent unit spacing.

Volumes are `tumor_voxels × slice_mm × row_mm × column_mm / 1000` in cm³. The PNG chooses `tumor_slice_indices[len(indices)//2]` (the upper middle for an even count), uses a fixed −1000..400 HU lung window, and overlays the exact corresponding mask plane. PNG pixels are native row/column order; the UI corrects physical aspect ratio using in-plane spacing. It labels the native CT plane and does not invent anatomical orientation labels.

## Artifact ownership and UI

Engine workspaces contain an ephemeral NPY working mask and PNG overlay, with role/media type/byte size/SHA-256 metadata. The private HTTP engine serializes only the display overlay into `data_base64` **before** leaving `EngineWorkspace`; the large NPY stays private and is cleaned up. The runner forwards retained bytes in results/snapshots/events, so History can retain them without depending on expiring paths. `path` is descriptive relative metadata, not a downloadable server URL.

`web/components/MaskResults.tsx` renders successful measurements/overlays and named failures/QC exclusions. The active Analysis page imports it, filters QC and mask result events separately, and shows both tool stages. History ticket #10 can use the same component or its generic result/artifact renderer; preserve `payload.stage` and the overlay bytes.
