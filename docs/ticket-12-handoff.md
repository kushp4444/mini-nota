# Live-run reconnect (#12)

The browser restores the newest nonterminal IndexedDB record, its opaque run secret, patient IDs, saved values/Blobs and last received sequence. `reconnectRun` in `web/lib/reconnect.ts` polls `GET /runs/:id/event-page?after=N&limit=20` through the application proxy. Page delivery is immediate and bounded (50 events maximum, 512,000 bytes of structured event metadata). Artifact transport bytes are removed from pages and replaced with authenticated same-origin `/api/runs/:id/artifacts/:sequence/:index` references; `captureEvent` collects actual bytes into local Blobs before advancing the local cursor. No history depends on those temporary references. The legacy SSE/snapshot API remains for compatibility, but the UI does not require a long stream or full-cohort snapshot.

Pages must be contiguous, agree with their cursors, and place a terminal event at the final server sequence with matching terminal status. A gap, stale cursor, invalid response or transport failure is never silently accepted as completion. Three transient retries are followed by a visible Retry reconnection control; computation is not canceled and the active browser run remains occupied. Requests/artifact fetches have 15-second client timeouts. Closing the tab sends no cancellation command.

403 (unusable saved secret) and 404 (temporary state lost/expired) produce a local failed record with an interruption explanation, preserved saved events/results/Blobs, and a requirement for a new computation. This recovery explanation is a local reason, not a fabricated server audit event or named user identity. Unreceived outputs cannot be reconstructed. Received metadata whose bytes are unavailable is retained as a named missing artifact. Temporary runner state still expires under its original cleanup policy; this ticket adds no durable visitor storage or listing.

## Lost creation responses and launch recovery

The #11 integration is now reconciled: `reserveBrowserRun` persists a high-entropy per-launch nonce and selected IDs in localStorage before contacting the runner. `/runs/launch-context` supplies a temporary runner incarnation token, which is also saved before POST. POST `/runs` accepts the nonce/context; repeated calls recover the same ID and secret, and a nonce reused for another selection is rejected. After browser-local credentials have actually saved, the marker changes to the ordinary opaque run reference. A lost POST response/reload retries the saved launch rather than freeing a possibly-live run or launching another computation. Terminal creation responses still drain all audit events from cursor zero before being saved as completed.

A lightweight in-memory nonce tombstone survives ordinary run/event expiration, so retrying an expired nonce cannot silently recreate work. If the runner incarnation changed or that nonce's temporary run was pruned, the runner first calls #11's private engine cancellation API using the nonce-derived opaque operation/run ID. The engine terminates/waits for the owned process and retains a cancellation tombstone blocking delayed subsequent stage calls. Only after this acknowledgement does the runner return `launch_interrupted`; the browser saves a failed local launch explanation, releases its marker, and requires an explicit new Run action. If the engine cannot acknowledge stopped work, the pending launch stays retryable and occupied. No automatic replacement computation is launched.

Deploy the external runner with one active owning instance/process and route its run requests consistently. These temporary capabilities and incarnation tokens are not a multi-worker routing or failover protocol. The private engine must retain ownership of its process groups; infrastructure must kill those owned descendants if the entire engine container is forcibly lost. No account/user identity or durable server visitor records are added. `launches` stores only temporary nonce-to-run/selection recovery tombstones in worker memory. The Vercel frontend proxies to this external owner and never stores a worker singleton.

Confirmed cancellation now aborts the current replay controller, then collects its authoritative tail through bounded event pages, rather than fetching an all-images snapshot. Saved pending records reclaim the same-browser marker if it is absent. Terminal persistence releases the marker; stale nonterminal events cannot overwrite terminal in-memory or IndexedDB records.
