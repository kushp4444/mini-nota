# Domain Docs

## Before exploring

Read root `GLOSSARY.md` and any ADRs in `docs/adr/` relevant to the area of work.
If these files are absent, proceed silently. Domain modeling creates them lazily when terms or decisions are resolved.

## Layout

This repo uses a single context:

- `GLOSSARY.md`: domain vocabulary for the whole repo.
- `docs/adr/`: architecture decision records.

## Vocabulary and decisions

Use glossary terms in issue titles, proposals, hypotheses, and test names. If a concept is missing, reconsider whether the term belongs and note real gaps for domain modeling.

Surface conflicts with an existing ADR explicitly, identifying the ADR and explaining why the decision should be reopened.
