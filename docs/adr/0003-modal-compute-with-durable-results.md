# Modal compute with durable results

The user selected Vercel for Next.js, a lightweight Render API, Neon PostgreSQL for metadata, extracted features and saved results, Cloudflare R2 for scans and generated artifacts, and Modal Functions for live imaging computation. This supersedes ADR 0001's prohibition on durable visitor results: remote jobs and saved outputs must survive the dispatcher sleeping or restarting, while the memory-intensive imaging pipeline runs outside the free dispatcher.

Live analysis still executes QC, mask construction, feature extraction and frozen-model scoring; precomputed results serve ordinary browsing and curated examples rather than masquerading as new computation. Keep scans and binary artifacts in object storage, with identifiers, structured results and object references in PostgreSQL. Persist the minimal job ownership, ordered audit and approval state needed for idempotent dispatch, cancellation, recovery and authenticated per-run result access; do not introduce accounts, session tracking or a public visitor-run listing.

Browser-local History remains available, including completed, canceled and failed results. Retain the existing one-active-run-per-browser rule, confirmed cancellation, named exclusions, explicit cohort/model-bound approval with no arbitrary deadline, and fixed model/evaluation semantics. An unanswered approval must release compute; losing a Render process must neither orphan a Modal job nor start a duplicate. Cloud credentials, actual deployment verification and measured usage are required before claiming a hosted demo or a zero-cost operating envelope.
